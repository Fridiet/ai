# OCR·레시피 식재료 세분화

## 조사 및 변경

기존 사전의 별칭을 검토해 71개 상위 묶음에서 207개 세부 이름을 명시적으로 관리합니다.
사전은 현재 610개 표준명입니다. 별칭은 표기 차이에 사용하고, 종류·부위·가공 상태가 다른 식재료는 분리합니다.
모든 상품 종류를 망라한 분류 체계라는 의미는 아닙니다. 종류가 불명확한 이름은 추측하지 않습니다.

대표 사례:

| 기존 통합 | 분리 예시 |
|---|---|
| 버섯 | 팽이버섯, 표고버섯, 양송이버섯, 새송이버섯, 느타리버섯, 목이버섯 |
| 고추 | 청양고추, 홍고추, 풋고추, 꽈리고추 |
| 닭고기 | 닭가슴살, 닭다리, 닭다리살, 닭날개 |
| 달걀 | 달걀흰자, 달걀노른자, 삶은달걀 |
| 치즈·두부 | 모짜렐라치즈, 체다치즈, 순두부, 연두부 |
| 가공식품→원료 | 감자칩/감자, 땅콩버터/땅콩, 메밀면/메밀, 훈제연어/연어 |

`ingredient_specificity.json`은 그룹 정보를 가집니다. 그룹은 화면 분류·제외 조건에 쓰지만,
서로 다른 하위 재료를 보유 재료로 간주하는 근거로 사용하지 않습니다.
부위만 적힌 안심·등심·목살은 축종을 임의로 소고기/돼지고기로 바꾸지 않습니다.
OCR의 세부 사전 일치를 상위 이름의 끝 일치 규칙보다 우선하도록 수정했습니다.

## 원본 레시피 복원

레시피 961개 중 식약처 원문이 있는 941개를 다시 파싱했습니다.
원래 데이터 대비 **763개 레시피의 재료 표현이 변경**됐고 최종 레시피 수는 961개로 유지했습니다.
정량 구간 10,798개 중 10,523개 매핑, 275개는 기존 제외 정책에 해당했습니다.
이는 파서가 처리한 구간 수이며 사람 검수 정확도 100%라는 뜻이 아닙니다.

원문이 없는 시드 레시피 20개는 종류를 지어내지 않았습니다.
원래 `버섯` 251개 재료 행은 표고 103, 팽이 37, 양송이 60, 새송이 57 등으로 복원됐습니다.
한 레시피의 여러 버섯이 이전에 한 행으로 합쳐졌으므로 분리 후 행 수 합계는 251보다 큽니다.
`표고크림파스타`는 표고버섯과 양송이버섯 두 재료가 각각 복원됐습니다.
일반 `버섯` 3행은 원문 없는 시드 2개와 원문 자체가 `미니버섯`인 1개로, 그대로 두었습니다.

초기 스냅샷과 변경 전후 목록: `output/ingredient_specificity/`.
반복 복원 시 `--recipes-input output/ingredient_specificity/recipes_ko.json.before.json`을 사용하면
중간 실험에서 격리된 행을 잃지 않고 최초 자료로 다시 검증할 수 있습니다.

## 추천과 모델 호환성

팽이버섯 재고로 표고버섯 요구량을 충족하지 않습니다. 일반 `버섯` 재고도 특정 종으로 추측하지 않습니다.
특정 재료를 검색하는 `targetIngredients`를 보유 재고에 강제로 추가하던 동작을 제거했습니다.
검색 대상으로만 지정한 재료는 실제 보유하지 않았다면 부족 재료로 표시됩니다.
반대로 제외 조건에서 `닭고기`를 지정하면 닭가슴살 등 하위 재료도 제외합니다.

레시피 ID가 같아도 재료 내용이 달라지면 구형 Two-Tower를 로딩하지 않도록 데이터 해시 검사를 추가했습니다.
최종 사전/레시피로 합성 context 30,752개를 다시 만들고 PyTorch Two-Tower를 40 epoch 재학습했습니다.
새 레시피 vocabulary는 572개입니다. 실제 사용자 행동 학습을 추가한 것이 아닙니다.
이전 모델은 `output/ingredient_specificity/previous_models`에 보관했습니다.

| 합성 test 3,844개 | 재학습 모델 | 재료 겹침 baseline |
|---|---:|---:|
| Recall@1 | 0.751821 | 0.758585 |
| Recall@5 | 0.913892 | 0.946670 |
| Recall@10 | 0.945890 | 0.973205 |

이번 학습은 새 vocabulary와 모델을 일치시키기 위한 것이며 baseline 대비 성능 개선을 입증하지 않았습니다.
OCR 분류기 v7 자체는 재학습하지 않았습니다. 이전에 합쳐 학습한 상위명 예측만으로 세부 재료를 확정하지 않고,
명시적 사전 근거가 없으면 검토 대상으로 남기는 안전장치를 사용합니다. Qwen 온라인 호출은 계속 0회입니다.

## 검증과 남은 한계

전체 Python 테스트 217개 통과. 종별 OCR, 원문 재료 복원, 동일 상위 그룹 간 재고 비동등성,
검색 대상의 가짜 재고 방지, 기존 개인화/제외 조건 회귀를 포함합니다.
일부 과거 회귀 정답은 새 규약에 맞게 고추→청양고추, 빵→식빵, 소고기→부채살로 바꿨습니다.
과거의 집계 정확도와 동일한 라벨 규약의 비교는 아닙니다.

`python -m scripts.verify_specificity_runtime`은 첨부 원본의 팽이버섯·청양고추 반환과
실제 추천 API에서 없는 표고버섯이 부족 재료로 나오는지 검증합니다.
이 원본 전체의 OCR 정확도 문제까지 해결한 것은 아닙니다. 오독된 상품, 미확정 식품, 일부 표 밖 행이
검토 목록에 남는 사례가 있으며 상세 결과는 runtime_verification.json에 보존합니다.

## DB 전환은 별도 승인 필요

이번 작업은 AI 파일과 로컬 모델만 변경했습니다. 기존 MySQL 데이터나 프론트/백엔드 파일은 바꾸지 않았습니다.
스키마를 당장 바꾸지 않아도 세부 표준명을 ingredient_master의 별도 행으로 관리할 수 있습니다.
다만 기존 `버섯` inventory의 ingredient_id를 팽이버섯으로 일괄 변경해서는 안 됩니다.
원본 영수증/사용자 확인이 있는 재고만 개별 매핑하고, 불명확한 재고는 일반 버섯으로 유지해야 합니다.
DB에 별도 저장된 레시피 catalog/alias는 새 파일과 동기화가 필요합니다. 기존 FK·사용자 저장 레시피·
피드백을 보존하는 마이그레이션을 설계하고 승인 후 적용해야 합니다. `seed_recipe_catalog.py`를 무작정 실행하지 마세요.
원격 push나 commit은 수행하지 않았습니다.

# OCR 분류기 API 적용

> 현재 운영 정책은 [경량 OCR 개선 결과](ocr-fast-pipeline.md)를 따릅니다.
> 아래 v25/Qwen 연결 설명과 이전 시간 측정은 변경 이력입니다. 현재 온라인 요청은 Qwen을 호출하지 않습니다.

## 적용 범위

`app/ocr_classification.py`가 기존 상품 행 분리 이후 v25 분류기를 호출합니다.
`POST /ocr`, `/api/ocr/receipt`, `/ocr/inventory-candidates`,
`/ocr/inventory-candidates/save`에서 공통 적용됩니다. `/ocr/raw`는 원문 그대로입니다.
이미지 문자 인식은 기존 PaddleOCR이며, 이번 변경은 상품명 후처리입니다.
프론트/백엔드 및 DB는 수정하지 않습니다.

## 결과 처리

- 먼저 비식품 명시어를 제외하고 기존 가공상품 사전의 정확/별칭/포함 일치를 유지합니다.
- 제한된 신선식품 목록의 가장 긴 상품명 끝 일치를 활용합니다. 양파·대파 등의 앞에 브랜드나
  수식어가 붙어도 인식하며, 복합상품/비식품 명시어와 여러 재료가 섞인 이름은 이 경로에서 제외합니다.
  포장 수량·단위만 제거하며 상품 전체의 의미를 바꾸는 단어를 삭제하지 않습니다.
- 위 근거 또는 기존 식재료 사전의 정확 일치가 있으면 모델을 호출하지 않습니다.
  근거 출처는 `receipt_fresh_suffix_rule`이며 점수 0.9는 규칙 점수이지 학습 정확도/확률이 아닙니다.
- 모델 점수가 기존 검증 임계값 0.5 이상이면 식품 이름 또는 비식품 판정을 반영합니다.
- 비식품 판정은 재고 후보와 수동 검토 후보에서 제외합니다.
- 임계값 미달이면 기존 식재료/가공식품 사전의 정확한 이름·별칭 일치만 유지합니다.
- 그 외 미확정 항목은 재고로 단정하지 않습니다. 기존 규약대로 구매 수량을 검산한 행은
  `reviewCandidates`로 전달하며, 수량을 검산하지 못한 행은 이 목록에서도 제외될 수 있습니다.
- 모델 파일/패키지 누락 또는 추론 실패 시 로그를 남기고 기존 사전 방식으로 처리합니다.
  로딩 실패는 요청마다 재시도하지 않으며 파일을 복구한 뒤 서버를 재시작해야 합니다.

기존 응답 필드는 유지합니다. 재고 후보 상세 응답의 `match_type`에 `ml_classifier`가 추가되며,
`source`는 `ocr_classifier_v25`입니다. 모델 점수는 보정된 확률이나 정확도가 아닙니다.
상품명, 구매 수량, 소비기한, 보관 위치는 사용자가 최종 확인해야 합니다.

## 실행 및 되돌리기

현재 로컬 `AI/.env`에서 활성화했습니다. 이 파일은 Git 제외 대상입니다.

```dotenv
OCR_CLASSIFIER_ENABLED=true
OCR_CLASSIFIER_MANIFEST=output/ocr_normalizer_experiment_v25/model.json
OCR_CLASSIFIER_THREADS=2
```

AI 디렉터리에서 실행:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000
```

기존 `start-all.ps1`도 AI/.env를 읽습니다. 되돌리려면 `OCR_CLASSIFIER_ENABLED=false`로 바꾸고
AI 서버를 재시작합니다. 환경변수를 설정하지 않으면 기본적으로 기존 사전 방식을 사용합니다.
이번에 생성한 .env에는 OCR 설정만 있으며 DB나 서비스 인증 설정을 새로 만들지는 않았습니다.

## 운영 조건과 한계

모델은 프로세스 시작 시 한 번 로딩하며, 추론은 잠금으로 직렬화하고 상품명 512개까지 캐시합니다.
모델 파일은 로컬에서만 읽으며 외부 추론 API를 사용하지 않습니다. 한 프로세스로 실행하세요.
추가 작업자마다 모델 메모리가 복제됩니다. 기존 실험의 분류 시간은 상품당 약 1.6초이며
최초 OCR 로딩·이미지 인식·대기 시간은 별도입니다. 긴 영수증은 클라이언트 제한 시간을 확인해야 합니다.

91.1%는 보류 전 개발 홀드아웃 45행 기준입니다. 현재 API는 보류 및 사전 fallback을 결합하므로
해당 수치를 API 전체 정확도로 주장할 수 없습니다. 전체 API의 독립 평가와 사람의 정답 검수가 필요합니다.

다른 컴퓨터에서는 추가 의존성 `requirements-ocr-experiment.txt`, v7 체크포인트,
v25 봉인 manifest, 고정 버전 E5/Qwen 로컬 캐시가 모두 필요합니다.
모델 출력 폴더는 Git 제외 대상이며 단순 clone만으로 새 모델이 배포되지는 않습니다.
재현 절차는 `ocr-normalizer-improvements.md`를 참고하세요.

## 검증

API 응답 스키마, 식품·비식품·보류, 사전 fallback, 파일 누락, 추론 예외, 캐시와 기존 OCR 회귀 테스트를 포함해
신선식품 매칭/복합상품 반례를 추가해 관련 100개 테스트를 통과했습니다. 운영 서버 점검 로그는 `output/ocr-api.stdout.log`,
`output/ocr-api.stderr.log`에 저장됩니다. 원격 서버 배포나 Git push는 하지 않았습니다.

로컬 영수증 `IMG00003.png`로 실제 HTTP 업로드를 확인했습니다.
`/ocr/inventory-candidates`는 HTTP 200과 `source=ocr_classifier_v25`를 반환했고,
`/api/ocr/receipt`도 HTTP 200으로 기존 `items`, `reviewCandidates` 필드를 반환했습니다.
재시작 직후 첫 이미지 요청은 OCR 초기화를 포함해 약 30~37초였습니다.
이는 연결 확인 1건이며 분류 정확도 평가를 추가로 수행한 결과는 아닙니다.

## 양파·대파 미분류 수정 검증

이전에는 `친환경복주머니양파`, `송송어린대파`의 모델 1순위 답이 맞아도 0.5 미만이어서
두 행 모두 빈칸으로 반환됐습니다. 현재는 신선식품 이름의 끝 일치 근거로 각각 양파·대파를
채우며 두 행 모두 추가 모델 추론 없이 처리됩니다. 오이스터·오징어짬뽕·양파링·샴푸·복합상품
반례 테스트를 함께 수행했습니다. 임계값을 낮추거나 개별 상품명 두 개를 별칭으로 추가하지 않았습니다.

`python -m scripts.verify_receipt_name_fix`는 동일 문구로 만든 한글 이미지로 실제 HTTP를 검증합니다.
두 품목 정확 반환, 검토 후보 0건, 후처리 약 0.02초, 이미지 포함 최초 약 6.7초/후속 약 0.6초를 확인했습니다.
원본 사용자 영수증 전체를 검증한 결과가 아니며 새로운 운영 정확도 수치로 해석하면 안 됩니다.
추가 변경으로 오류가 없는 것은 아니므로 더 많은 실제 상품/비식품 검증이 필요합니다.
`output/receipt_name_fix_http.json`에 결과를 저장합니다.
서버 로그는 이미지 인식 시간과 상품 후처리 시간 및 분류 출처별 개수를 분리해 남깁니다.

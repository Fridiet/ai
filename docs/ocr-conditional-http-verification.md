# 기존 보조 OCR 조건부 HTTP 검증

2026-09-12. 실행 중인 8000 서버와 별도로 127.0.0.1:8011에 임시 서버를 실행했다. 프론트·백엔드·DB는 수정하지 않았다. 재고 저장이 아닌 `/api/ocr/receipt` 분석 경로만 요청했다.

## 개발용 전체 비교

기존 보조960 캐시가 없던 IMG00254/IMG00298을 원본 해시와 development 분할을 확인한 후 인식했다. 이로써 같은 21장 비교에서 기본은 이름 54/74·수량 51/91·동시 29/74, 기존 보조960 조건부는 이름 54/74·수량 58/91·동시 36/74다. 새 민감도960 조건부는 동시 35/74로 기존보다 낮다. 잘못 확정한 수량은 세 방식 모두 0건이다.

정답은 AI 보조 검수 개발 초안이며 독립 성능이 아니다. 동시 정답은 보관 위치·날짜 검증을 포함하지 않는다. `secondary_profile_comparison.json`은 이제 21장을 모두 포함한다. 19장 비교 수치는 앞선 실험 문서에 보존했다.

## 임시 서버 설정

- OCR_CLASSIFIER_ENABLED=true
- OCR_SECONDARY_COUNTS_ENABLED=true
- OCR_SECONDARY_NAME_HINTS_ENABLED=false
- OCR_DETECTION_MAX_SIDE=0

환경 변수는 임시 서버 프로세스에만 적용했다. 프로젝트 `.env` 및 기본 설정은 변경하지 않았다.

## 실제 HTTP 결과

3장에 최초 1회+반복 2회, 총 9회 직렬 요청했다. 전부 HTTP200, 사진별 응답 해시가 일치했다.

| 이미지 | 반복 HTTP 시간 | 보조 OCR 동작 |
|---|---|---|
| IMG00254 | 2.73 / 2.71초 | 호출 안 함 |
| IMG00051 | 6.54 / 6.58초 | 호출, 수량 2행 보완 |
| IMG00238 | 5.75 / 5.78초 | 호출, 수량 1행 보완 |

반복 6회 표본 중앙값 5.77초, 표본 p95 6.57초다. 최초 IMG00254 요청은 7.90초였으며 서버 로그의 엔진 생성 시간이 5.03초였다. 이를 여러 PC·동시 사용자 환경의 p95 또는 SLA로 해석하지 않는다. 사진별 2회 반복뿐이며 순서도 고정했다. 서버 로그상 보조 처리에 약 1.88~1.96초가 추가됐다.

결과: `output/receipt_readiness/api_secondary_conditional_20260912.json`. 응답 본문은 저장하지 않고 해시와 항목 수만 기록했다. 이미지별 실제 품목 정답률은 앞선 캐시 평가와 구분한다. 브라우저 화면 또는 DB 저장까지의 E2E 테스트는 아니다.

검증 후 임시 서버를 종료했다. 기존 8000 서버는 재시작하지 않았으므로 이번 설정이 현재 사용자 화면에 반영됐다고 주장하지 않는다. 목표 달성에는 남은 수량·이름 오류 개선, 추가 검수와 독립 평가가 필요하다.

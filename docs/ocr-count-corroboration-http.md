기존 8000 서버는 변경하지 않고 루프백 8011에 현재 AI 코드를 실행했다.
분류기 켬, 보조960 수량 켬, 이름 힌트 끔, 기본 검출 크기 설정0,
DB 자동 생성 끔으로 실행했다. `/api/ocr/receipt` 분석 요청만 사용했다.

## 응답 검증

`scripts.verify_count_corroboration_http`의 실제 이미지 두 장 요청이 성공했다.

- 밀가루: 2.5kg와 가격 열 복원 안내가 함께 반환됨.
- 우유: 손상된 m1을 1800ml로 확정하지 않고 포장당 용량 확인 안내 유지.
- 청오이/백오이: 구체적인 재료명과 vegetable 분류 유지.

이 네 조건의 확인이지 영수증 전체가 무수정 등록 가능하다는 뜻이 아니다.
결과: `output/receipt_readiness/count_corroboration_http.json`.

추가 포장량 부분 재인식 실험 기능은 이 서버에 적용하지 않았다.
기존 다른 이미지 벤치마크와 비교해 이번 코드가 느려졌다고 해석할 수 없다.

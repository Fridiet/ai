# 검출 해상도와 등록 품질 비교 (2026-09-12)

## 범위

- `evaluation/new_receipts_development.json`의 개발용 검수 초안 27장만 사용했다. 동결 평가 30장은 사용하지 않았다.
- 동일 프로세스에서 각 이미지의 기본 설정, 최대 3,200픽셀 설정 순서로 실제 OCR을 실행했다. 분류 모델은 활성화했다.
- 모델 초기화 시간은 제외한 OCR 추론 시간이다. HTTP 지연 시간이나 반복 측정 SLA가 아니다. 순서 효과도 통제하지 않았다.
- 아래는 **1차 OCR + 후처리** 결과다. 헤더 재인식·960픽셀 보조 인식·숫자 셀 재인식을 더한 전체 API 지표와 구분해야 한다.

## 결정과 다음 검증

- 운영 설정과 8000번 서버는 변경하지 않았다. 속도 개선 완료로 보고하지 않는다.
- 실험 스크립트에 max2400/max3200 프로필을 추가했다.
- 향후 3,200픽셀을 검토하려면 보조 인식까지 포함한 동일 조건 API에서 수량 회복 여부, 늘어난 보조 인식 시간, 개별 행 변화까지 비교해야 한다. 이번 결과만으로 전체 파이프라인이 14% 빨라진다고 주장할 수 없다.
- 전 이미지 축소 외에도 상품 영역 검출/인식 단계별 비용을 확인해야 한다. 영수증 가장자리나 하단 상품이 누락되지 않는지 검증 없이 자르지 않는다.

원본 결과: `output/new_receipts/detector_experiment/summary-default-max3200.json`, `summary-default-max1600-max960-subset-IMG00722.json`, `summary-max2400-max3200-subset-IMG00722.json`.

검수 초안 자체가 독립 정답이 아니며 반복 개발에 사용됐다. 일반화 정확도나 전체 목표 달성률로 제시하지 않는다.

## 보조 인식 포함 후속 비교

`compare_receipt_secondary_profiles`에 명시적 1차 캐시 선택과 실제 헤더 재인식 옵션을 추가했다. 기존 보고서를 덮어쓰지 않도록 프로필별 파일로 저장한다.

27장 모두에서 1차 OCR·960 보조 OCR은 저장된 결과를 사용하고, 헤더와 숫자 셀은 원본 이미지로 실제 재인식했다. 따라서 이는 전체 HTTP 성능 측정이 아닌 **혼합 재생 품질 비교**다. 재인식 시간에는 해당 프로세스의 첫 모델 초기화가 포함될 수 있다.

| 보조 인식까지 포함 | 기본 | 최대 3200 |
| --- | ---: | ---: |
| 정확한 이름 | 102/124 | 102/124 |
| 올바른 구매 개수 | 104/143 | 99/143 |
| 이름·구매 개수 동시 일치 | 80/124 | 75/124 |
| 올바른 포장 내용량 | 25/38 | 24/38 |
| 잘못 확정한 구매 개수 | 0 | 0 |

축소로 인한 손실은 보조 인식으로도 전부 복구되지 않았다. 일괄 해상도 축소안은 운영 적용 후보에서 제외한다. 기본 설정의 80/124는 약 64.5%이지만 소비기한·보관·포장 확인까지 끝난 자동 등록률은 아니다. 기본에서도 확인 경고가 있는 식품 후보가 97개이며, 이름이 틀린 라벨 항목 5개와 분류 보류 16개가 남는다.

실행 명령:

```powershell
.\.venv\Scripts\python.exe -m scripts.compare_receipt_secondary_profiles --existing-only --numeric-runtime --header-runtime --primary-profile default
.\.venv\Scripts\python.exe -m scripts.compare_receipt_secondary_profiles --existing-only --numeric-runtime --header-runtime --primary-profile max3200
```

결과: `output/new_receipts/numeric_runtime_comparison-default-header.json`, `numeric_runtime_comparison-max3200-header.json`.

다음 품질 개선은 남은 기본 설정 실패 행에 집중한다. 실제로 존재하는 수량 칸의 글자를 읽는 문제와 제품 정체성 불명확 문제를 분리한다. 할인율 기호나 충돌 숫자를 단순 제거해 수량을 맞추지 않는다.

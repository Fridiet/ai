# OCR 상품별 GPT 보관기간 제안

AI `/ocr`, `/api/ocr/receipt`의 등록 준비 결과에 포함된
분류된 식품에 적용한다. 2026-10-04부터 기존 매퍼 추정 날짜도 GPT에 다시 요청한다.
실제 제품 표시 날짜/기존 DB 재고에는 적용하지 않는다. 상품명 정규화 기능과 독립적이며
원문 OCR·직접 DB 저장에는 적용하지 않는다.
모든 분류된 식품을 대상으로 표준명·안전 검사한 상품명·카테고리·보관 방식·
보관 근거/상태·행 ID를 OpenAI에 전송한다. K-FIND에서 매칭한 상품도
재료 사전에 없다는 이유로 제외하지 않는다. 이미지, 전체 영수증 행,
수량, 가격, 사용자 개인정보는 보내지 않는다. 의심스러운 상품명은 전송하지 않는다.

## 설정

`OPENAI_API_KEY`와 `OPENAI_OCR_MODEL=gpt-5.4-mini`를 기존처럼 사용한다.
`OCR_SHELF_LIFE_LLM_ENABLED=true`가 기본값이다. `false`로 설정하고 재시작하면 중지한다.
기존 상품명 보정 `OCR_LLM_ENABLED` 및 용기 잔량 설정은 바꾸지 않는다.
요청당 최대 20항목, 영수증의 모든 대상 항목을 여러 요청으로 나눠 처리한다.
자동 재시도 없음. 모든 요청의 대기·검증을 포함해 이 단계 전체 최대 8초.
시간 초과/일부 요청 실패 때 이미 검증이 완료된 요청 결과는 유지한다.
상품명 보정도 켜면 두 단계 시간은 합산될 수 있다. 프로세스 내 동시 요청 제한 2개를 공유한다.

## 의미와 제한

이 날짜는 **제품 표시 소비기한이 아니라 일반적인 보관·확인 알림 제안**이다.
GPT는 상품별 보관 방식과 일수를 제안하고, 서버가 범위와 행 ID를 검증한 뒤
처리일 + 일수로 날짜를 만든다. `reviewNotes`에 조건·기준일·실제 안전 보장이 아님을 명시한다.
기존 매퍼 추정 날짜는 다시 계산하지만 수량·단위·상품 원문은 변경하지 않는다.

미확인 보관 방식도 추정하여 `locationCategory`에 채우지만 실제 상태를 확인한 것은 아니다.
새로 구매한 식품, 포장 제품은 정상적인 미개봉 상업용 포장을 조건부로 가정한다.
실제 상태를 확인한 것은 아니다. 맥주는 개봉한 잔여 맥주가 아닌 미개봉 캔·병을 가정한다.
실온 제안은 통과일/일부 통채소·곡물·조미료·미개봉 맥주/건면/통조림 및
명시적으로 멸균된 미개봉 우유/두유 등에만 반영한다. 신선 우유·생육·손질 과일에는 적용하지 않는다.
상품명에 명시된 냉동/냉장은 우선한다. 해동/조리 후 남은 음식은 냉장으로 구분한다.
기존 CANONICAL_RULE의 보관 방식은 추정 힌트이므로 GPT가 교정할 수 있지만,
명시적인 보관 조건/사용자 확인은 변경하지 않는다. PRODUCT_LABEL/USER_CONFIRMED/SAVED
출처의 실제 날짜는 재요청/덮어쓰기 대상이 아니다.
냉장은 4°C 이하, 냉동은 -18°C 이하를 가정한다. 해당 조건을 지켜도 이전 보관 이력과
오염 여부를 알 수 없으므로 안전을 보장하지 않는다. 오래 구매한 음식에 처리일 기준을 적용하지 않는다.

음료 3일 등의 카테고리별 GPT 상한은 제거했다. 1~730일 정수만 허용하는
형식 검증을 사용하며, 이것은 식품 안전 기준이 아니다. 중복/누락/잘못된 행 ID는 거절한다.
맥주 등의 품질 유지 기간을 안전 보장으로 해석하지 않는다. 제품 표시가 있으면 표시를 우선한다.
GPT 단계 자체는 API 장애, 키 없음, 시간 초과, 불확실 판정, 범위 위반에 기존 결과를 유지한다.
운영 응답을 만들기 직전 `finalize_registration_items`가 분류된 `items`의 남은 빈 날짜를
보관 방식+카테고리별 일반 보관 알림 일수로 채운다. 냉동 가공식품은 90일,
냉장 도시락/조리된 피자 등의 대체 알림은 최대 3일이다. 이는 앱 대체 정책이지
검증된 상품 소비기한이나 GPT 응답이 아니다. 냉동 제품에 냉장 기본 3일을 넣지 않는다.
보관 위치가 비어 있으면 상품명의 명시적 보관 정보를 먼저 적용하고, 없을 때만 냉장을 가정한다.
내부 `_date_source`에 GPT/CATEGORY_FALLBACK/STORAGE_CATEGORY_FALLBACK을 구분한다.
`_product_name`, `_storage_source`, `_date_source`는 외부 응답에 노출되지 않는다.
수량·단위·기존 날짜·이미 알려진 보관 방식은 변경하지 않는다.
이는 제품 소비기한 확인이나 실제 냉장 보관 여부의 증명이 아니며, 오래 보관된 음식에는 적용하지 않는다.
미분류는 계속 `reviewCandidates`로 반환해 식품/재료명이 없는 자동 등록 항목을 생성하지 않는다.

2026-10-04 사용자 요청으로 외부 `reviewNotes`는 빈 배열로 반환한다. 화면에 이미 있는 상단의
소비기한/보관 위치 추정 안내만 유지하여 항목마다 긴 확인 메시지가 반복되지 않도록 했다.
프론트는 수정하지 않았으며 상단 안내의 문구 자체는 기존 문구다. 내부 검증·수량 근거·보정 상태는 유지한다.
AI 응답 외의 수동 입력/다른 경로에서 빈 날짜를 보내는 경우의 백엔드 필수 검증은 별도 보완이 필요하다.

## 2026-10-04 검증

아래는 맥주 수정 당시의 917개 테스트/단일 상품 결과이다. 맥주 모의 응답 180일 반영, 기존 3일 추정 덮어쓰기,
수량 보존, 오류 시 기존 날짜 보존을 검증했다.
실제 `gpt-5.4-mini` 단일 상품 요청에서 맥주 → 실온 180일,
2026-10-04 기준 2027-04-02를 받았다. 한 번의 조건부 응답이며 모든 맥주의
확정 소비기한이나 정확도 평가가 아니다. 실제 영수증 검증 결과는
`output/receipt_llm/beer_storage_receipt.json`에 저장했다. 운영 API는 HTTP 200,
식품 11개 중 GPT 날짜 9개 반영, 나머지 2개는 검증 조건에 따라 기존 날짜 유지,
빈 날짜 0개·항목별 확인 메시지 0개였다. 맥주는 실온 180일/2027-04-02로 반환되었다.
날짜 제안 단계는 1.857초였다. DB에 이미 등록된 날짜는 수정하지 않았다.

## 전체 상품 요청 / 냉동 상태 개선 검증

`python -m scripts.verify_receipt_storage_live`로 실제 GPT에 가상 상품명 10개를 요청했다.
10개 모두 GPT 결과가 반영되었다(1.459초). 냉동 피자/만두/아이스크림/감자튀김은
냉동 180일, 냉장 소고기/조리된 남은 피자는 냉장 3일, 냉장 우유는 7일이었다.
결과: `output/receipt_llm/product_storage_live.json`.
이는 연결/상태 구분 검증이며 상품의 실제 기한 정확도 평가가 아니다.
맥주 등 모델 일수는 요청별로 달라질 수 있으며 특정 브랜드의 표시 기한으로 해석하지 않는다.
추가 테스트는 사전 밖 분류 상품, 45행 분할 요청, 부분 실패, 장애 시 냉동 대체값,
개봉/해동/손질 상태, 개인정보/주입 차단, 수량 보존 및 내부 필드 비노출을 다룬다.

최종 전체 테스트 948개 통과. 실제 운영 `/api/ocr/receipt` 영수증 검증은 HTTP 200,
분류 식품 11개 모두 GPT 날짜 반영(로그 accepted=11), 빈 날짜/반복 안내 0개였다.
GPT 날짜 단계 1.341초, OCR 초기 로딩 등을 포함한 전체 서버 처리 16.055초였다.
결과는 `output/receipt_llm/all_product_storage_receipt.json`에 저장했다.
피자 API 경로는 별도 계약 테스트에서 상품 DB 매칭 후보를 주입해 두 OCR 경로의
상품 정보 전달/냉동 날짜 반영을 검증했다. 실제 냉동 피자 사진의 OCR 정확도를
검증한 것은 아니며, 냉동 피자 보관기간 실제 GPT 연결은 가상 상품명 테스트로 확인했다.

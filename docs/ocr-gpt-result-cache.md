# GPT 영수증 결과 재사용 (2026-10-27)

## 적용 범위와 안전장치

AI의 영수증 상품명 보정과 보관 기간 제안에만 적용한다. OCR 인식 모델,
이미지 해상도, 수량 복구, DB 저장, 용기 사진 추정은 변경하지 않는다.

- `OCR_LLM_CACHE_ENABLED=true`로 활성화한다. 환경 변수가 없으면 비활성이다.
- 프로세스 메모리 한정, 최대 1,024건, 유효기간 1시간, LRU 제거.
  디스크·DB에 캐시를 쓰지 않으며 재시작 시 사라진다.
- 식별 키는 SHA-256이다. 모델, 프롬프트, 구조화 응답 스키마, 행 문맥을 포함한다.
  상품명 보정은 표준 재료 사전 전체의 재료명·별칭도 포함한다.
- 상품 행 식별자는 키에서 제외하고 조회 시 현재 행 번호로 재연결한다.
  상품명·후보 목록 및 ID·보관 위치·위치 고정 여부·개봉/해동/조리 상태 등이
  다르면 키가 달라진다. 부분 적중이면 미적중 행만 GPT에 보낸다.
- 기존 개인정보·프롬프트 주입 필터를 통과한 행만 캐시 경로에 진입한다.
- 상품명은 `supported` 검증을 통과한 판단만 저장한다. 불확실·거절·원문 근거
  부족·서버 검증 실패·중복/잘못된 행 식별자·API 장애 결과는 저장하지 않는다.
- 소비기한은 검증을 통과한 `storage`와 `days`만 저장한다. 절대 날짜를 저장하지
  않고 현재 처리일에 days를 더한다. 제품 표시·사용자 확인·저장된 날짜는 제외한다.
- 적중하더라도 기존 `apply_decisions`/`apply_suggestions` 검증을 다시 수행한다.
  캐시가 검증이나 원문 수량 근거를 우회하지 않는다.
- API 키·이미지·영수증 전체·원문 가격·구매 개수는 캐시하지 않는다.
  상품명 보정 값에는 검증된 재료 판단·원문 근거 부분 문자열·설명만 포함된다.
  로그에는 기존 시간/건수/오류유형/토큰 수와 `cache_hits`만 남긴다.

인증, 분당/일일 제한 해제 상태, 동시 처리 및 유한 대기열은 유지한다.
검증되지 않은 판단을 억지로 재사용하지 않으므로 모든 GPT 요청이 없어지는 것은 아니다.
동시에 처음 들어온 동일 상품 요청 간 중복 호출 억제는 이번 변경에 포함하지 않는다.

## 검증

- 새 캐시 테스트 30개, 전체 AI 테스트 **1,084개 통과**.
- 캐시 활성/비활성 결과 동등성, 원본 불변성, 수량·가격·구매 개수 근거 보존,
  행 번호 재연결, 모델/프롬프트/사전/상품 문맥 변경 시 미적중 검증.
- 오징어짬뽕→오징어, 팽이버섯→양송이버섯, 불명확한 그릭 무가 등 잘못된
  제안이 캐시되지 않는지 검증. 현재 검증기가 적중 결과에도 적용됨을 확인.
- 보관 기간 다음 날 재계산, 개봉·해동·위치·카테고리·제품명 변경, 실제 표시 날짜
  보존, 유효기간/용량 상한, 오류·중복 ID, 부분 적중, 반환값 변조 격리 검증.

실제 AWS 주문내역 이미지 **1장(5개 상품)**을 3회 순차 처리한 결과:

| 요청 | 서버 왕복 | 등록 후보 | 미분류 |
|---|---:|---:|---:|
| 캐시 비어 있음 | 12.342초 | 5 | 0 |
| 재사용 1회 | 8.283초 | 5 | 0 |
| 재사용 2회 | 10.021초 | 5 | 0 |

3회 전체 응답 JSON이 동일했다. 응답 SHA-256:
`9c2d3686b12d2c308a1644c94138f105e869c67297e086c9fe10c3e754730aa5`

상품명 보정 5건 중 4건 적중, 보관 기간 5건 모두 적중.
GPT 상품명 처리 3.021초 → 1.576/3.354초(미검증 1건은 계속 재요청),
보관 기간 처리 1.853초 → 0.003/0.003초.
GPT 토큰 합계 2,397 → 667/672.
실제 GPT 요청 비용은 발생했으나 검증용 재고·식사·캘린더 DB 쓰기는 하지 않았다.

이는 재사용 전후 결과 보존 및 지연을 확인한 단일 이미지 시험이지,
전체 영수증의 정답 정확도 평가가 아니다. 별도의 수작업 정답셋 정확도 수치나
새 상품에서도 같은 속도가 나온다고 주장하지 않는다. 처음 보는 상품·문맥,
캐시 만료·서버 재시작 시 기존 GPT 호출이 필요하다.

## 배포와 비활성화·복구

AWS에 `receipt_result_cache.py`, `receipt_llm.py`, `receipt_shelf_life.py`와
`OCR_LLM_CACHE_ENABLED=true`만 반영하고 기존 시작 준비를 유지했다.
외부 HTTPS health 200을 확인했다. 프론트·백엔드·DB 스키마 수정 없음.
커밋·푸시 없음.

비활성화: root 전용 `/etc/fridiet-ai.env`에서
`OCR_LLM_CACHE_ENABLED=false`로 설정하고 `sudo systemctl restart fridiet-ai`.
모델 시작 준비가 끝나면 기존 GPT 호출 경로로 복귀한다.
환경 파일에는 비밀 키가 있으므로 출력·공유하지 않는다.

배포 전 백업: `/var/backups/fridiet/receipt-cache-20261027-143947/`
수동 복구 시 이 디렉터리의 `app/receipt_llm.py`, `app/receipt_shelf_life.py`를
`/opt/fridiet-ai/app/`의 해당 파일로 복원하고, 환경 파일도 기존 위치로 복원한다.
새 캐시 모듈은 기존 두 모듈 복원 후 사용되지 않는다.
환경 파일 권한 600을 유지한 뒤 서비스를 재시작한다.
배포 도구는 예상 기존 파일 해시가 다르면 덮어쓰지 않고 중단하며,
서비스 준비 실패 시 코드·설정을 자동 복원한다.

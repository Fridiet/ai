# 헤더 재인식의 전체 보정 경로 대비 효과

2026-09-12. 정답 초안 27장의 기존 검출에서 숫자 열 제목 하나가 빠지고 나머지 두 제목이 있는 후보를 선택했다. 3장이 해당했고 24장은 재인식하지 않았다. 후보 선택에는 정답 수량을 사용하지 않았다.

| 영수증 | 헤더 추가 | 기존 보조 OCR/숫자 보정 포함 구매 개수 정답 | 이름·개수 동시 |
|---|---:|---:|---:|
| IMG00218 | 1 | 16→18 | 14→16 |
| IMG00004 | 0 | 0→0 | 0→0 |
| IMG00722 | 0 | 11→11 | 7→7 |

수량을 단언한 오답은 세 경우 모두 0이었다. 첫 성공 요청은 모델 로드를 포함하여 9.314초였다. 이후 실패한 두 후보는 각각 0.838/0.813초로, 성공 경로의 웜 지연으로 해석하지 않는다. 실패한 재인식으로 기존 텍스트를 교체하지 않았다.

script: `python -m scripts.experiment_receipt_header_recovery --all-eligible`

report: output/new_receipts/header_recovery_all_eligible.json

처음 실행은 일부 기본 OCR 캐시가 detector_sensitivity_all에만 있어 중단됐다. 해당 캐시 경로를 지원한 뒤 정상 종료까지 다시 실행했다. 동결 평가 이미지는 사용하지 않았다. 결과는 개발용 초안 비교이며 운영 API에 아직 연결하지 않았다.

기존 헤더가 중복되거나 낮은 신뢰도일 때는 보충하지 않는 검사도 추가했다. 실제 API 연결 및 전체 지연 검증이 다음 단계다.

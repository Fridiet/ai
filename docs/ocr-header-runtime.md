# 조건부 헤더 재인식 API 검증

2026-09-12. `/ocr`와 `/api/ocr/receipt`에 OCR_HEADER_RECOVERY_ENABLED 옵션을 추가했다. 기본 false이며 원시 OCR 경로는 변경하지 않았다. 숫자 열 제목 2개가 고신뢰도로 남은 단일 헤더에서만 원본 영역을 한 번 재인식한다. 기존 본문은 바꾸지 않고 검증된 누락 제목 하나만 추가한다. 오류 시 원래 결과를 유지한다.

임시 8011 서버에서 분류기/960 보조 수량/숫자 셀/헤더 옵션을 켰다. IMG00218와 IMG00722를 각각 3회 요청해 6회 모두 200, 이미지별 응답 해시 동일을 확인했다. 218은 제목 한 개 보충, 722는 실패하여 보충 0이었다. 추가 요청에서 백오이5개와 파프리카1봉이 복원 안내와 함께 반환됨을 검증했다. 백오이 구매1봉의 내용물5개와 파프리카 구매1봉은 같은 단위로 뭉개지지 않았다.

초기 요청은 16.654/16.520초, 반복은 218에서 10.827/10.116초, 722에서 15.688/15.842초였다. 헤더 추가 단계는 약 0.5~0.94초. 초기 구간에 pytest가 병행되어 부하가 통제된 성능 비교가 아니며, 다른 크기의 이전 영수증 측정값과 직접 비교하지 않는다. 큰 이미지의 기본 OCR 추론 약 14~15초가 지연의 주원인이다.

735개 테스트 통과. disabled일 때 파일을 읽지 않는지, 헤더 없으면 추론하지 않는지, 오류 시 원본 유지 여부를 포함한다. 보고서: output/receipt_readiness/api_header_recovery_20260912.json. 임시 서버는 종료했고 8011 리스너가 없음을 확인했다. 8000 운영 서버는 변경하지 않았다.

응답의 소비기한/보관 위치는 기존 추천값이며 이번 검증이 실제 제품 표시 기한의 정확성을 증명하지 않는다. 동결 평가와 프론트/백엔드/DB/원격 저장소는 건드리지 않았다.

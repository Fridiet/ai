# OCR 상품명 분류 모델 실험 v1

## 구현과 학습

PyTorch로 문자 1·2·3-gram 특징을 사용하는 다중 클래스 로지스틱 회귀 모델을 학습했습니다.
문자열 특징을 4,096차원으로 해싱하고, 교차 엔트로피 손실로 분류 가중치를 학습합니다.
학습 클래스는 식품의 정규화 분류명과 `__NONFOOD__`입니다. 이미지 OCR 엔진이나 레시피 Two-Tower를 재학습한 것이 아닙니다.
맞춤법 문자열 생성 모델도 아닙니다. OCR 문자열을 기존 식품 분류에 연결하는 실험입니다.

- 전체 연결 후보 298행 중 학습 208행 / 검증 45행 / 개발 홀드아웃 45행
- 동일 영수증 그룹, 동일 상품명, 동일 OCR 문자열을 전이적으로 묶은 69개 그룹으로 분리
- seed 42, AdamW, 학습률 0.025, 최대 250 epoch, 검증 손실 기준 체크포인트 선택
- 원본 AI 주석과 자동 연결은 사람 검증 정답이 아닙니다. 사용자의 명시적인 실험 학습 요청으로만 사용했습니다.
- 원본 `training_eligible=false` 표시는 변경하지 않았습니다. 실험 보고서에 별도의 명시적 사용 승인을 기록했습니다.

## 개발 홀드아웃 결과

| 항목 | 결과 |
|---|---:|
| 평가 행 | 45 |
| 상품 분류 정확도 | 75.6% (34/45) |
| 최근접 문자열 비교 기준선 | 53.3% (24/45) |
| 최빈 클래스 기준선 | 55.6% (25/45) |
| 식품 Precision, 보류 적용 전 | 100% (10/10) |
| 식품 Recall, 보류 적용 전 | 50% (10/20) |
| 학습에 없던 정답 클래스 행 | 5 |
| 점수 0.65 이상 채택 | 28/45 (62.2%) |
| 채택한 행의 분류 정확도 | 89.3% (25/28) |

검증셋에서 최소 5건 채택 및 정확도 90% 조건으로 보류 임계값 0.65를 선택했습니다.
홀드아웃에서는 그 정확도가 89.3%였으며 90%를 보장하지 않습니다. softmax 점수는 보정된 정답 확률이 아닙니다.
보류 정책을 적용한 수치와 적용 전 식품 Precision/Recall을 혼용하면 안 됩니다.

**운영 적용은 보류했습니다.** 학습 정확도는 100%이나 홀드아웃에서 식품 절반을 놓칩니다.
자료가 작고 비식품으로 치우친 판단이 있습니다. 미학습 클래스는 예측할 수 없고, 점수가 높아도 오분류할 수 있습니다.
또한 156장을 이미 개발 과정에서 열람했으므로 위 결과는 독립적인 최종 테스트 성능이 아닙니다.
문자열이 실질적으로 다른 교정 후보는 전체에서 22행뿐이므로 일반적인 OCR 오타 교정 성능 향상을 주장할 근거도 부족합니다.

## 산출물과 재현

AI 폴더에서 실행합니다. 출력은 Git 제외된 로컬 실험 폴더입니다.

```powershell
.\.venv\Scripts\python.exe -m scripts.train_ocr_normalizer --allow-assistant-labels
.\.venv\Scripts\python.exe -m pytest tests/test_ocr_normalizer.py tests/test_receipt_pairs.py tests/test_receipt_visual_review.py -q
```

- `output/ocr_normalizer_experiment_v1/model.pt`: 실제 학습 가중치, 클래스, 특징 차원, 보류 임계값
- `training_report.json`: 데이터 SHA-256, 학습 손실 이력, 분리별 측정값, 실험 한계
- `split_manifest.json`: 각 분리에 들어간 파일 및 주석 행
- `heldout_predictions.json`: 개발 홀드아웃의 정답·예측·점수

추론은 `app.ml.ocr_normalizer.ExperimentalNormalizer`로 체크포인트를 명시적으로 불러옵니다.
FastAPI 등록이나 기존 모델 자동 로딩 경로에는 연결하지 않았습니다. DB, 프론트, 백엔드, Two-Tower 체크포인트는 변경하지 않았습니다.

다음 개선은 보류된 OCR–정답 연결을 검증해 식품·오타 사례를 늘리는 것, 클래스별 데이터 보강, 사람이 확인한 새 영수증 평가입니다.

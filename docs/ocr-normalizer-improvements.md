# OCR 상품명 분류 개선 실험

> 후속 변경: 로컬 서비스 API에 v25 어댑터를 연결했습니다. 아래는 연결 전 실험 기록이며,
> 현재 실행 정책과 보류/fallback은 [API 적용 문서](ocr-classifier-api.md)를 따릅니다.

## 범위

영수증 이미지에서 글자를 읽는 OCR 엔진이나 레시피 Two-Tower를 재학습하는 작업이 아닙니다.
읽힌 상품명 문자열을 **표준 식품 품목 또는 비식품**으로 분류하는 후처리 모델입니다.
운영 API에 연결하지 않은 로컬 실험이며, 변경 범위는 AI 폴더입니다.

## 결과 — 개발 홀드아웃 91.11% (41/45)

최종 실험 v25는 **학습 분류기 + 사전학습 언어모델 + 변경 제한 규칙**을 결합해
개발 홀드아웃 전체 상품 분류 정확도 **91.11% (41/45)**를 기록했습니다.
학습한 분류기 단독 성능은 v7의 **88.89% (40/45)**입니다. 규칙이나 외부 사전학습 지식의 효과를
직접 학습한 모델의 성능으로 바꾸어 설명하면 안 됩니다. 운영 API는 교체하지 않았습니다.

**개발 자료에서의 90% 목표는 달성했지만, 독립 테스트나 실서비스 정확도 90%를 보장한 결과는 아닙니다.**

| 지표 | v25 결과 |
|---|---:|
| 검증 세트 전체 정확도 | 88.89% (40/45) |
| 개발 홀드아웃 전체 정확도 | 91.11% (41/45) |
| 식품 여부 Precision | 100% (20/20) |
| 식품 여부 Recall | 100% (20/20) |
| 식품만 대상으로 한 세부 품목 정확도 | 80% (16/20) |
| 보류 없이 전체 평가한 영수증 | 21장, 상품 45행 |
| 점수 0.5 이상 채택된 행 | 15/45 |
| 채택된 행만의 정확도 | 93.33% (14/15) |

**채택 정확도 93.33%를 전체 정확도 또는 목표 달성으로 주장하면 안 됩니다.**
45행 중 비식품이 25행이므로 전체 정확도와 식품 세부 품목 정확도 역시 서로 다릅니다.
단순 행 독립을 가정한 Wilson 구간도 약 79.3~96.5%이며, 실제로는 같은 영수증 내 행이
서로 연관되고 AI 주석을 사용했으므로 이 구간도 일반화 성능의 보증이 아닙니다.

### 최종 구성

1. v7 분류기가 OCR 상품명에 대해 표준 품목/비식품 점수를 계산합니다.
2. 상위 식품 후보, 상품명에 포함된 품목명, 비식품을 최대 16개 보기로 구성합니다.
3. 로컬 [Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)가 상품명과 보기를 함께 읽습니다.
   자유 텍스트를 생성하지 않고 A~P 선택지 토큰의 점수만 계산합니다. Qwen은 이 프로젝트에서 추가 학습하지 않았습니다.
4. 검증 세트로 선택한 온도 1.0과 가중치 0.1로 보기 점수와 기존 분류기 점수를 결합합니다.
5. 다른 식품으로 바꾸려면 상품명 끝의 가장 긴 품목명 일치(2글자 이상) 또는 기존 정확한 상품명 매핑이 필요합니다.
   근거가 없으면 기존 분류를 유지합니다. 이 안전장치는 명시적 규칙이며 학습된 지능이 아닙니다.

Qwen revision은 `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`, 계산 형식은 BFloat16입니다.
제품명 매핑은 기존 가공식품 사전에서 가져온 전체 문자열 매핑을 모델 설정에 고정합니다.
특정 평가 상품명에 대한 예외 규칙은 추가하지 않았습니다.

v10의 클래스 균형 SVM은 검증 정확도 최대 66.67%였고 메타데이터 저장 오류로 완성되지 않았습니다.
저장 오류는 v11에서 수정했으며 v10 부분 산출물은 사용하지 않습니다.
검증이 나빠진 모델을 개발 홀드아웃 결과만 보고 채택하지 않았습니다.

### v25에서 남은 오분류

| OCR 상품명 | 주석 정답 | v25 출력 |
|---|---|---|
| 우유케이크 | 케이크 | 아이스밀크 |
| 촉촉치즈후레쉬팡 | 빵 | 우유 |
| 보누치/와플/스트로베리 | 와플 | 빵 |
| 샤인머스켓 | 샤인머스캣 | 포도 |

기존 v7에서 비식품으로 누락됐던 피자 상품은 v25에서 피자로 분류됐습니다.

향·원재료와 완제품 종류를 혼동하는 오류, 브랜드/축약명, 상·하위 품목 정답의 일관성이 과제입니다.
특히 샤인머스캣/포도처럼 범주 수준이 다른 이름을 임의로 같은 정답으로 처리해 정확도를 높이지 않았습니다.

다음 우선순위는 품목 정답 체계 통일과 어려운 복합 상품명의 학습 자료 보강입니다.
그 후 개발에 사용하지 않은 새 마트 영수증을 사람이 확인한 정답으로 평가해야 합니다.
이미 열람한 156장을 다시 나누는 것만으로 독립 테스트가 되지는 않습니다.

## 모델과 학습 자료

- 문자 1·2·3-gram 해시 특징 4,096차원과 고정된 다국어 E5 문장 특징 384차원을 결합합니다.
- PyTorch 선형 분류기의 가중치를 교차 엔트로피로 학습합니다. E5 자체는 재학습하지 않습니다.
- 사전학습 인코더: [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small).
  revision은 `614241f622f53c4eeff9890bdc4f31cfecc418b3`으로 고정합니다.
- OCR 연결 후보 298행은 기존 분할인 학습 208 / 검증 45 / 개발 홀드아웃 45행을 유지합니다.
- 학습용 영수증의 추가 시각 주석, 기존 식재료 사전, 가공식품 사전, 로컬 K-FIND 상품 DB를 보강 자료로 사용합니다.
- K-FIND는 고정 난수로 품목별 최대 12개 상품을 뽑습니다. 넓은 품목을 섬세한 식재료 동의어로 간주하지 않습니다.
  빵류 등 명시한 범주 통합은 별도 함수로 관리합니다.
- v7은 K-FIND 252개 품목의 2,794행을 보강하고, 정규화 후 겹치는 학습 예시 68행을 제외했습니다.
  최종 학습 예시는 증강·사전 항목을 포함한 5,909개이며 실제 영수증 5,909장을 의미하지 않습니다.
- 검증에서 선택된 설정은 E5 특징 가중치 0.5, 클래스 균형 지수 0.5, 75 epoch입니다.

## 누수 방지와 평가 한계

동일 영수증 그룹과 반복 상품명을 묶은 최초 분할을 유지합니다. 추가 시각 주석은 평가 영수증 및
그 영수증에 등장하는 상품명을 제외합니다. K-FIND 보강에서는 평가 상품명과 정규화 후 같거나
매우 유사한 이름을 제외합니다. 수량·용량 제거 후 같아지는 학습 영수증 예시도 제외합니다.
독립적으로 존재하던 표준 식품 사전 및 학습 클래스 이름은 외부 지식으로 사용하며,
평가 상품과 같은 일반명(예: 시금치)이 존재할 수 있습니다. 사전 지식 없는 분류 실험이 아닙니다.

`audit_ocr_training_separation`으로 원본 seed 42 분할을 다시 계산해 기존 분할과 일치함을 확인했습니다.
평가 자료의 원본 해시도 일치하며, 직접 학습한 영수증/합성 예시와 평가 상품명의 중복은 0건입니다.
학습용으로 뽑은 K-FIND 상품명과 평가 상품명의 정확한 중복, 추가 시각 주석의 평가 영수증 그룹 중복도 0건입니다.
이 검사는 **직접 학습 자료의 분리**를 검증하며, 반복 실험에 따른 개발 평가의 낙관적 편향까지 없애 주지는 않습니다.

v4/v5 추가 감사에서 수량 제거 후 일부 학습·평가 상품명이 같아지는 문제가 발견됐습니다.
이 버전의 40/45를 중복까지 차단한 최종 성능으로 인용하면 안 됩니다. v3은 상·하위 식품명을
잘못 동의어로 합친 문제로 폐기했고, v6 학습은 추가 누수 방지를 적용하기 위해 중단했습니다.

**156장 모두 이미 개발 과정에서 열람했고, 정답은 사람이 확정한 라벨이 아닌 AI 주석입니다.**
따라서 홀드아웃이라는 파일명에도 불구하고 독립 최종 테스트가 아닙니다. 개발 오류를 보고
설계를 개선했고, 학습 설정 선택은 검증 세트로 수행합니다. 새 영수증에 대한 90% 보장은 아닙니다.
여러 방식과 규칙을 반복 비교했으므로 새로 수집한 자료에서 성능이 낮아질 수 있습니다.
전체 이미지에서 상품행을 못 찾는 오류, OCR 글자 오류, 수량 오류는 이 분류 지표에 포함되지 않습니다.

## 재현

AI 폴더에서 기존 프로젝트 가상환경과 로컬 K-FIND DB, 156장 주석 및 v1 분할 파일이 필요합니다.
주석과 학습 산출물은 `output/`에 있어 Git clone만으로 재현되지는 않습니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ocr-experiment.txt
.\.venv\Scripts\python.exe -m scripts.train_semantic_ocr
.\.venv\Scripts\python.exe -m scripts.verify_semantic_ocr --folder output/ocr_normalizer_experiment_v7
.\.venv\Scripts\python.exe -m scripts.audit_ocr_training_separation
.\.venv\Scripts\python.exe -m scripts.rerank_ocr_choices --include-nonfood --choice-model Qwen/Qwen3-1.7B --safety-gate --all-food-switches
.\.venv\Scripts\python.exe -m scripts.verify_ocr_choice_model --folder output/ocr_normalizer_experiment_v25 --seal
```

처음 실행할 때 공개 사전학습 인코더를 다운로드합니다. 영수증을 외부 추론 API로 보내지는 않습니다.
재로딩 검증은 캐시의 인코더만 사용하며 네트워크 다운로드를 허용하지 않습니다.

최종 결과는 `output/ocr_normalizer_experiment_v25/training_report.json`,
`heldout_predictions.json`, `reload_verification.json`으로 확인합니다.
정확도는 보류 적용 전 **45행 전체**를 분모로 계산합니다. 보류한 행을 제외한 채택 정확도와 혼동하면 안 됩니다.
`model_score`는 분류기와 선택지 점수를 결합한 값이며 보정된 정답 확률이 아닙니다.

v25는 캐시된 평가 점수를 재사용하지 않고 모델 두 개를 다시 읽어 45건을 재실행했습니다.
분류/점수 불일치는 0건이며, 원본 평가 행과 정답이 바뀌지 않았는지도 확인합니다.
첫 재실행 측정은 CPU 2개 스레드에서 상품당 평균 약 1.60초였습니다. 모델 로딩 시간은 제외한 값이며
다른 CPU/수치 형식에서는 속도와 미세한 수치 차이가 있을 수 있습니다.
관련 단위/회귀 테스트 47개가 통과했습니다.

간단한 로컬 실행:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.predict_ocr_product --text "국산양파 1kg"
```

`app.ml.choice_ocr_normalizer.ChoiceOCRNormalizer`를 재사용할 수 있습니다.
모델 설정, 기반 체크포인트 및 추론 코드 해시를 고정하며, 변경되면 기존 검증 결과를 그대로 사용하지 않도록 거부합니다.
`model.json` 하나만 복사해서 실행할 수는 없습니다. 기반 v7 체크포인트와 E5/Qwen 로컬 캐시도 필요합니다.
검증 실행은 `local_files_only=True`로 외부 모델 다운로드 및 외부 추론 요청을 하지 않습니다.
운영 API 연결·서버 재시작·DB 저장 구조 변경은 하지 않았습니다.
실험 결과만 로컬에 보존하며 커밋·원격 푸시는 수행하지 않았습니다.

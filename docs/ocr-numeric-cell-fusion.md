# 숫자 영역 증거를 이용한 수량 병합

`app/receipt_numeric_cells.py`에 검증된 세 숫자와 기존 행 매칭을 결합했다.
세 필드 형식·confidence>=0.9·산식을 검사한 후 보조의 두 가격과 일치하는지,
원본/보조 각각의 숫자 모순, 행 위치/이름, 중복 및 일대일 대응을 확인한다.
기존 수량은 덮어쓰지 않고 새로 복구한 값의 출처만 NUMERIC_CELLS_VERIFIED로 표시한다.
스키마와 확인 안내도 추가했다. 재인식은 같은 모델을 사용하는 추가 증거이며
독립적인 모델들의 합의라고 해석하지 않는다.

## 개발25장 캐시 재생 (2026-09-12)

- 기존 보조960 방식 개수98/141 → 숫자 영역 결합100/141.
- 이름+개수72/122 →74/122.
- 감자칩과 드레싱 각1개 복구. 이름과 총량 지표는 불변이다.
- 잘못 확정한 구매 개수0 유지.
- 고등어는 금액confidence가0.9 미만이라 채택하지 않았다.
- 숫자 충돌이 있던 포도음료는 원문7을1로 덮어쓰지 않았다.

평가자료는 개발용 초안이며 독립 정확도가 아니다. 숫자 영역 검출이 가능한
11장 캐시만 사용하고 나머지는 기존 결과를 유지했다. 결합 결과는
`output/new_receipts/numeric_cell_fusion_comparison.json`에 기록했다.

현재는 수량 병합 함수와 응답 출처 준비까지다. `app.main`의 HTTP 처리에서
재인식 함수를 호출하도록 연결하지 않았으며 운영 서버도 재시작하지 않았다.
실제 호출의 모델 재사용, 시간 제한, 실패시 기존 결과 유지, 지연 측정이 남아 있다.
DB/프론트/백/학습 모델/원격 저장소 변경 없음.

# 포장량 부분 재인식 실험 (2026-09-12)

## 목적과 범위

상품명이 맞더라도 포장량이 잘못 읽혀 자동 등록이 실패하는 원인을 확인한다.
`scripts.experiment_package_recognition`은 개발 분할의 원본 SHA-256을 검증하고,
가격이 있는 상품 영역에 속한 한글+숫자 OCR 조각만 0/3px 여백으로 재인식한다.
전화번호·회원 정보·환불 안내 등 상품 영역 밖 조각은 제외한다.
결과는 진단 파일에만 기록하며 운영 API, DB, 학습 데이터에는 반영하지 않는다.

실행: `.\.venv\Scripts\python.exe -m scripts.experiment_package_recognition IMG00059.png IMG00664.png`

## 실제 실행 결과

- IMG00059: 36개 crop, 재인식 약 1.599초.
- IMG00664: 16개 crop, 재인식 약 0.606초.
- 시간은 인식 호출만 포함하며 모델 초기화, 분류, 원본 OCR, HTTP 전체 시간이 아니다.

| 기본 OCR | 0px 결과 | 3px 결과 | 판단 |
|---|---|---|---|
| 닭정육82kg | 닭정육8 2kg | 닭정육8 2kg | 기존 파서는 두 결과에서 모두 2kg 추출 가능 |
| 이스트89 | 이스트8g | 이스트89 | 결과 불일치. 자동 확정 근거 부족 |
| 우유900m1*2입 | 동일한 m1 오독 | 동일한 m1 오독 | 재인식만으로 단위 복구되지 않음 |

이스트의 틀린 `89` 출력이 맞는 `8g`보다 인식 신뢰도가 높았다.
따라서 높은 confidence만 선택하는 방식은 이 사례를 해결하지 못한다.
같은 모델의 두 crop 결과 일치도 독립적인 정답 검증은 아니다.

## 다음 구현에 대한 판단

전체 영수증을 반복 처리하기보다 포장량 불확실 항목의 영역을 제한해 재인식하는
경로를 검증할 가치가 있다. 하지만 이 두 장만으로 자동 적용하지 않는다.
이름/행 대응, 변경 전후 숫자와 단위, 기존 구매 개수 증거를 보존하고,
추가 개발 영수증에서 잘못된 보정률과 지연을 함께 평가해야 한다.
닭고기의 구매 개수는 여전히 미확정이므로 2kg 후보만으로 총 재고량을 확정할 수 없다.

출력: `output/new_receipts/package_recognition_experiment.json`.
검증: 전체 pytest 600개 통과. 운영 서버 미재시작, 프론트/백엔드 및 DB 변경 없음.
독립 평가용 frozen 이미지는 사용하지 않았다.

## 검수된 개발 23장 확장 비교

`--all-development`로 23장의 상품 조각을 재인식하고,
`python -m scripts.evaluate_package_recognition`으로 같은 원본 OCR에 대한 오프라인
대조 실험을 수행했다. 원본 캐시 해시도 저장·검증하며 두 여백 결과의 텍스트와
파싱된 포장량이 일치하고 신뢰도 각각 0.85 이상인 변경만 시험했다.
공백을 지운 텍스트만 같더라도 `82kg`와 `8 2kg`처럼 수량이 다르면 거부한다.

- 포장량 정답이 있는 23항목: 14 → 15개 일치.
- 기존 정답 유지 14, 오답 유지 8, 오답→정답 1, 정답→오답 0.
- 재료명 정확 일치 79/100 유지, 이름 변경 없음.
- 구매 개수 정답 69/119 유지.
- 구매 개수 증거까지 갖춘 총량 정답 9개 유지.
- 채택된 시험 변경은 닭정육82kg → 닭정육8 2kg 한 건뿐이다.

이는 재료명을 판별할 수 있는 100항목 전체의 재고량 정확도가 아니다.
총량 정답이 없는 항목은 총량 회귀 여부를 판정할 수 없다.
이번 비교는 **기본 OCR 대 부분 재인식**이며, 구매 개수용 보조960 OCR을
포함한 비교(개수80/119)와 분모만 같다고 직접 섞어 비교하면 안 된다.

판단: 현재 실험으로 자동 등록 준비 항목의 증가를 입증하지 못했다.
운영 기본값 변경은 하지 않는다. 추가 재인식 자체보다 구매 개수 증거 복구가
병목이며, 이후 총량 보정은 구매 개수 및 사용자 확인 필요 상태와 함께 검증한다.
전체 테스트 604개 통과.

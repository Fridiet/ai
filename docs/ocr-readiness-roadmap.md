# 사진 → 재고 등록 초안: 진행 중인 목표

최종 목표는 모든 식품을 억지로 분류하는 것이 아니라, 대부분의 식품을 정확히 채우고 불확실한 항목만 확인받는 것이다. 현재 완료 판정은 하지 않는다.

## 현재 추가 진행

완제품과 포함 재료를 혼동하는 경로를 추가 보완했다. 명시적 빼빼로·크라상/크루아상·웨하스·호떡은 각각의 제품명으로 유지하고 아몬드·생크림·바닐라·옥수수로 등록하지 않는다. 제품 종류 뒤에 과자/우유/믹스 등이 더 붙는 복합 상품은 단순 접미사 규칙으로 승격하지 않는다. 안심신선특란·안심신선란도 달걀 판정에 포함했다.

이전 주석의 `과자`, `빵`과 새로운 `빼빼로`, `크루아상`은 정답 표현의 세부 수준이 다르다. 이를 정확도 증가로 임의 계산하거나 기존 정답을 모델 출력에 맞춰 바꾸지 않는다. 실제 포함 재료 오분류가 해소됐는지와 문자열 일치 점수는 구분해서 검토한다. 테스트 351개 통과.

같은 98장 원본 OCR 캐시를 재분석한 결과는 `output/receipt_readiness/after-confectionery.json`에 기록했다. 직전 기본 검출 결과 대비 이름 일치 133→137건, 이름 불일치 33→31건, 이름·수량 동시 일치 70→71건, 수량 일치 125건 유지다. 학습/개발에 노출된 주석이므로 독립 성능이 아니다. 검출 설정은 기존값을 유지하고 분류 수정만 로컬 AI 서버에 반영했다.

검출 해상도·영역 분할·부분 재인식 결과는 `receipt-detection-experiment.md`, 신규 사진 분할 및 주석 상태는 `new-receipt-dataset.md`에 기록한다. 독립 평가와 대부분 항목의 자동 등록 준비는 아직 완료하지 않았다.

## 완료 기준 제안

학습·규칙 수정에 사용하지 않은 새 영수증을 별도로 확보하고 이미지 단위로 고정한다. 날짜·보관 조건은 영수증에 없는 경우 추정/확인이 필요하므로 자동 확정 대상에서 제외한다.

- 자동 채움 재료명 precision 95% 이상, 전체 구매 식품 이름 recall 85% 이상을 1차 목표로 설정.
- 재료명과 구매 수량이 모두 맞는 항목 비율, 사진당 사용자 수정/추가 횟수도 함께 측정.
- 속도는 동일 PC·동일 이미지에서 cold/warm, 대기/로딩/인식을 분리하고 p50/p95 보고.
- 이 수치는 목표이며 달성된 성능이 아니다. 표본 수와 신뢰구간 없이 일반 성능을 단정하지 않는다.

## 2026-09-12 1차 변경

- POS 행 번호 `003 롯데...`가 가격으로 해석되어 이름 전체가 사라지던 오류 수정.
- 이름/가격이 두 줄로 나뉜 경우, 가까운 숫자 행만 보수적으로 연결. 서로 다른 상품이나 합계 행은 연결하지 않음.
- 기울어진 OCR 상자 간 작은 수직 겹침 허용.
- `1,980*`, `3,000#`, `9, 980` 가격 표시 지원. 구매 수량은 단가×수량=금액 검산을 통과할 때만 확정.
- 점으로 표시된 천 단위 가격이 상품명에 남아 분류 모델을 방해하지 않도록 처리.
- 기존 API 응답 형식 유지. 대기/엔진 로딩/인식 및 요청 전체 시간 로그 추가.

## 개발용 98장 진단

기존 156장 중 마트/편의점 98장, 구매 식품 주석 311행을 동일 OCR 스냅샷으로 비교했다. 이 자료는 이미 학습·개선에 노출되었으며 AI 주석이고, 과거 넓은 분류명도 포함된다. 텍스트 정렬은 근사적이므로 아래는 독립 정확도가 아닌 원인 진단이다.

| 지표(건) | 변경 전 | 1차 변경 후 |
|---|---:|---:|
| 상품 행 필터/정렬 실패 의심 | 141 | 10 |
| 재료명 주석과 정확히 일치 | 47 | 121 |
| 구매 수량 일치 | 27 | 115 |
| 재료명·구매 수량 동시 일치 | 8 | 56 |
| 분류 보류 | 70 | 113 |
| 이름 불일치(주석 검토 포함) | 23 | 40 |

이름 불일치와 보류가 증가한 이유 중 하나는 이전에 통째로 누락되던 행이 분류 단계에 도달하기 때문이다. 이를 숨기거나 90% 정확도라고 표현하지 않는다. 아직 자동 등록 준비 목표와 차이가 크다.

실행: `python -m scripts.audit_receipt_readiness --output output/receipt_readiness/report.json`

236개에서 추가 회귀 사례 2개를 더해 전체 테스트 238개 통과. 실사진 API 결과는 `output/receipt_readiness/live.json`에 기록한다. 스냅샷 평가 시간은 문자 인식 시간을 포함하지 않는다.

## 남은 순서

### 3차: 정확한 상품 DB 근거 연결

K-FIND/MFDS의 상품명 **정확 일치**와 식품유형을 함께 확인하는 `catalog_identity` 정책을 추가했다. 같은 이름의 후보들이 서로 다른 재료 정체성을 지시하면 확정하지 않는다. 퍼지/부분 일치는 이 승격 경로에서 제외하고, 이미 정확히 알고 있는 세부 재료명(예: 감자칩)은 넓은 법적 분류(과자)로 덮어쓰지 않는다.

실사진의 사조 참치액은 DB 정확 일치와 소스 유형을 근거로 `참치액`으로 자동 채워졌다. 참치나 기타 소스류로 바꾸지 않는다. 해당 사진은 자동 채움 3개/확인 11개로 아직 목표에 미달한다. 전체 테스트 258개 통과. 기존 개발용 98장에서는 정확한 이름 126→127건, 자동 채움 167→168건이며, `output/receipt_readiness/after-catalog.json`에 기록했다.

### 2차: 상품 문맥 및 비상품 행

브랜드 `서울우유`가 포함됐다는 이유만으로 커피까지 우유로 확정하던 경로를 제한했다. 스틱·칩·커피 등의 가공 문맥과 일부 과자 브랜드는 생재료 접미사 규칙보다 먼저 고려하며, 이 신호 자체로 특정 과자를 확정하지는 않는다. 모델이 없을 때도 충돌하는 부분 일치로 되돌아가지 않는다.

POS 할인 상세(`[번들]50%`, `[M+N] 1+1`)와 재사용 봉투, 상품 표 이후 면세/과세 합계 아래 결제 내역을 구분한다. 정상 상품명이 있는 할인 상품 행은 유지한다.

동일 98장 스냅샷에서 자동 채움 167건 유지, 정확한 이름 일치 121→126건, 이름 불일치 40→35건, 이름·수량 동시 일치 56→59건. 여전히 개발용 AI 주석 기준이며 독립 정확도가 아니다. 과자 브랜드의 모든 일치를 막는 대신 생재료 후보에 한해 차단하여 명시적인 크래커는 유지한다. 전체 테스트 252개 통과. 최종 상세 결과 `output/receipt_readiness/after-context-final.json`.

롯데마트 실사진에서는 크래커·삼겹살이 유지되고, 잘못 채워지던 고구마/감자/우유는 확인 대상으로 전환됐다. 확인 대상은 비상품 행 제거와 함께 14→12개가 되었다. 이것은 해당 사진이 대부분 자동 완성됐다는 뜻이 아니며, 14개 구매 식품 중 자동 채움은 아직 2개뿐이다. 로컬 카탈로그의 정확한 `사조참치액` 조회가 존재하지만 법적 식품유형 `기타 소스류`와 사용자 재료명 사이의 연결은 추가 개발해야 한다.

1. 분류 보류/오분류를 OCR 오탈자·축약명·가공품과 원재료 혼동·사전 부재로 분리하고 원문 이미지 대조.
2. 확인된 상품 근거 기반 후보 검색을 적용. 근거가 부족한 약칭은 확정하지 않고 후보/확인으로 유지.
3. 필요할 때만 이미지 재인식 또는 보조 모델을 비교 실험. 효과·오분류·지연을 함께 비교하고 검증 전 기본 경로에 넣지 않음.
4. 새 영수증으로 독립 평가. 기존 데이터의 이름만 holdout으로 변경하지 않음.
5. 화면의 후보 선택/확인 UX 변경이 필요하면 사용자 승인 후 프론트/백엔드와 연결.

소스 변경은 AI 안에서만 했으며 DB/사용자 재고 변경과 커밋/푸시는 하지 않았다.

# 상품명 / SKU·수량·단가·금액 행 구조

2026-09-12 개발 이미지 확장 및 개선.

## 새 자료와 정답 초안

추론 전에 원본을 확인한 IMG00130/IMG00131을 추가했다. 개발 정답 초안은 29장, 식품 160행, 이름이 확정된 136행이다. IMG00127 세정제 영수증과 IMG00129 버거 매장 영수증은 별도 비식재료/음식점 검토 목록에 기록했다. 동결 평가 이미지는 사용하지 않았다. 회원·결제 식별자는 라벨에 전사하지 않았다.

새 두 장의 원본은 이름 다음 줄이 `SKU 수량 단가 금액 T`인 반복 구조다. 쿠폰은 별도 상품명과 `-T` 금액을 갖는다. 동일 상품의 반복 구매 행은 각각 유지한다. CRISP SPICY의 정확한 식품 종류와 동원 참치의 처리 형태는 원문만으로 확정하지 않았다.

## 구현 범위

- 6~8자리 SKU, 관측된 1~99 수량, 100원 이상 단가, 단가×수량=금액, 마지막 T를 요구한다.
- 숫자 행의 OCR 신뢰도가 모두 0.9 이상이어야 하고, 인접한 이름/숫자 행 쌍이 적어도 2개 있어야 이 구조를 선택한다.
- 원본 글자·좌표는 보존한다. 숫자 행은 상품 정체성 추출에서 제외하고 검증 수량으로 별도 전달한다.
- `쿠폰` 제목 + `IRC` 상품명 + 음수 금액이 인접한 3행은 구매에서 제외한다. 일반 음수 반환 상품을 이 규칙으로 삭제하지 않는다.
- WHEAT TORTILLA(S)는 완전 일치 시 또띠아로 분류한다. CHIPS/FLOUR/MIX를 또띠아로 바꾸지 않는다.

## 검증과 한계

변경 전 새 두 장의 수량 정답은 0/17이었다. 행 구조 개선 후 12/17로 증가했고, 쿠폰에서 생기던 정답 외 식품 후보는 5→0이다. 이 결과는 최초 27장의 정확도 상승으로 섞어 보고하지 않는다.

기존 98장 캐시 점검(행 구조 개선 후, 마지막 영어 이름 규칙 추가 전)은 이름 138/303, 구매 수량 141/311, 동시 일치 74/303, 잘못 확정한 수량 0으로 기존 집계와 같다.

전체 테스트는 기본 분류 모델 비활성 환경에서 768개 통과했다. 그 전에 평가용 `OCR_CLASSIFIER_ENABLED=true` 환경을 그대로 이어 실행했을 때 기존 사전 단독 기대 테스트 2개가 실패했다. 테스트를 수정해 숨기지 않았고, 기본 테스트 설정으로 재실행했다. 모델 활성 경로는 별도 개발 이미지 재생으로 확인한다.

실행 중인 8000 서버는 이 변경 이전 코드다. 해당 서버에 행 구조 수정까지 반영했다는 뜻은 아니다. 실제 HTTP 신규 이미지 확인이 다음 단계다.

최종 29장 혼합 재생(모델 활성, 헤더·숫자 셀 실제 재인식): 이름 113/136, 이름·구매 개수 89/136, 구매 개수 116/160, 잘못 확정한 구매 개수 0. 명칭 라벨 미확정 24행은 이름 정확도 분모에 넣지 않았으며 최종 독립 평가가 아니다. 라벨은 개발 분할과 대조하고 중복 파일명도 확인했다.

## HTTP 확인 및 추가 보완

그 다음 단계에서 숫자에 붙은 `T`도 공백이 있는 `T`와 같게 처리했다. 음수 `-T`는 여전히 구매 수량 검증에서 제외한다. 새 두 장의 검증된 숫자 행은 5+9=14개로 증가했다. 남은 손상 코드·낮은 신뢰도·충돌 숫자는 보정해 확정하지 않는다.

기존에는 SKU가 손상되면 상품명과 금액이 분리되어 `CRISP SPICY 2 KG`가 확인 목록에서 사라졌다. 반복 SKU 구조가 이미 확인된 문서 안에서는 손상된 숫자 행도 상품명에 연결하되, 검증 수량을 부여하지 않고 원문·금액 근거만 유지하도록 했다. 검증된 상품 행 2개 이상이라는 진입 조건은 유지한다.

HTTP 검증은 처음에 물의 24L 응답을 24000ml로만 기대해 실패했다. 두 단위의 실제 부피를 환산하는 검증으로 고쳤다. 제품 수량을 바꿔 통과시키지 않았다.

8011에서 신규 두 장의 반복 또띠아 구매 보존, 물의 총 부피, 쿠폰 제외, 미분류 영문 상품의 확인 목록 보존을 확인했다. 이후 8000 로컬 서버를 현재 코드로 재시작하고 기존 4장+신규 2장 총 6개의 선택된 HTTP 검증이 모두 통과했다. 결과는 `output/receipt_readiness/http_semantics_8000.json`이다. 8011은 종료했다.

현재 전체 테스트 769개 통과. 최종 코드의 기존 98장 캐시 평가(`after-sku-pending.json`)도 이름 138/303, 수량 141/311, 동시 일치 74/303, 잘못 확정한 수량 0을 유지했다. 위 29장 전체 집계는 마지막 보완 이전 스냅샷이므로 갱신 전까지 최신 총계로 인용하지 않는다.

여전히 매장 주소·계산원 등 잡문구가 일부 확인 목록에 남고, 디너롤·체다 등 미분류 및 불확실한 영문 식품도 있다. 6개 검증 통과가 모든 상품의 자동 등록 완료를 뜻하지 않는다. DB 데이터 및 프론트/백엔드 변경은 없다.

## POS 안내·주소 정리 후속

아래 내용은 변경 순서에 따른 기록이다. 최신 결과는 문서 끝의 디너롤·체다치즈 검증을 참고한다.

`Reg # 숫자 Trans # 숫자`, `CASHIER: 이름 REG#숫자`, `REG#숫자`의 완전한 형식만 안내문으로 제외했다. 도로명 주소는 시도명·도로명·건물번호·T/TEL 표식·전화번호가 모두 있을 때만 제외한다. 상품명 속 Reg/Cashier, 서울우유, 세종당근 등의 문자열은 제외하지 않는 테스트를 추가했다.

코스트코 두 장의 실제 HTTP 확인 후보가 각각 6→3, 8→7로 줄었다. 정상 반환 상품은 물 1개+또띠아 3개 / 물 3개+또띠아 2개로 유지했고, 쿠폰·주소·계산원 안내 부재와 미분류 영문 상품 보존을 검증했다. 8000 서버에 반영되어 실행 중이다. 전체 테스트 784개 통과, 최종 기존 98장 집계는 `after-sku-pending.json`과 동일하다(`after-pos-address-metadata.json`).

## 디너롤·체다치즈 검증 (2026-09-12)

완전한 상품명 `뉴디너롤36CT`와 `KS마일드체다907G`를 각각 디너롤과 체다치즈로 정규화한다. 믹스·소스·크래커 같은 복합 상품은 해당 규칙으로 구성 재료에 축약하지 않는다. 디너롤은 모닝빵과 구분하고 빵의 하위 품목으로 유지한다.

명시된 디너롤 CT 표기만 포장 개수로 해석한다. `36CT`와 검증된 구매 개수 2가 함께 있으면 72개다. 구매 개수 근거가 없으면 포장 개수 36을 후보로 제공하되 `PURCHASE_QUANTITY_REQUIRES_CONFIRMATION`을 반드시 유지한다. 이를 단위 테스트로 고정했다.

전체 테스트 793개 통과. 기존 98장 캐시 집계는 이름 138/303, 구매 개수 141/311, 동시 일치 74/303으로 유지됐다(`after-bulk-bread-cheddar.json`). 29장 개발 혼합 재생은 이름 116/136, 구매 개수 118/160, 동시 일치 92/136, 총수량 32/50이다. 구매 개수 근거까지 요구하면 총수량 일치는 28/50이다. 캐시와 실제 부분 재인식을 결합한 개발용 진단이며 독립 정확도나 자동 등록률이 아니다.

8000 로컬 AI 서버를 최신 코드로 재시작하고 선택된 영수증 6장의 HTTP 의미 검증을 모두 통과했다. IMG00130의 디너롤 72개, IMG00131의 체다치즈 907g을 응답에서 확인했다. 두 장의 미분류 확인 후보는 각각 3→2, 7→5로 줄었다. 여기서 확인 후보 수는 이름이 있는 항목의 수량·보관 경고를 포함하지 않으므로 사용자 수정 필요율로 해석하면 안 된다. 검증 보고서는 `output/receipt_readiness/http_semantics_8000.json`이다. 프론트·백엔드와 DB는 변경하지 않았다.
